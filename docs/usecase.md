# 수학학원 랜딩페이지 상세 유스케이스 문서

---

## 1. 액터 정의 (Actor Definitions)

* **주요 액터 (Primary Actor)**: 학부모 (중·고등학생 자녀의 수학 교육을 위해 웹사이트에 접속하여 정보를 탐색하고 상담을 예약하는 사용자)
* **시스템 액터 (System Actor)**: 프론트엔드 웹 애플리케이션 (사용자의 입력 및 스크롤 인터랙션을 처리하고, 레벨 진단 로직과 방문 예약 폼 유효성 검증을 수행하는 단일 페이지 시스템)

---

## 2. 종합적 액터 정의 (Comprehensive Actor Definitions)

* **학부모**: 별도의 회원가입(인증) 절차 없이 랜딩페이지에 접속하여 학원의 통계 실적, 강사진, 차별점, 수강 후기를 종합적으로 검증하고, 자녀의 수준을 진단하거나 오프라인 방문 예약을 진행하는 주체입니다.
* **클라이언트 프론트엔드 시스템**: 데이터베이스 연동 없이 브라우저 메모리 영역에서 동작하며, 상단바 스크롤스파이, 인터랙티브 위젯(레벨 진단, FAQ 아코디언), 그리고 예약 폼 입력값을 실시간으로 처리하는 정적 웹 환경입니다.

---

## 3. 유스케이스 시나리오 (Use Case Scenarios)

* **UC-01 (상단바 및 스크롤 탐색)**: 사용자가 상단바(Topbar) 메뉴를 클릭하거나 스크롤하여 원하는 정보 섹션으로 이동하는 시나리오
* **UC-02 (온라인 수학 레벨 진단)**: 사용자가 진단 위젯의 문항에 응답하여 학생의 예상 레벨과 추천 강좌를 실시간으로 확인하는 시나리오
* **UC-03 (자주 묻는 질문 확인)**: 사용자가 FAQ 아코디언을 토글하여 수강료 및 보충 수업 규정 등의 궁금증을 해소하는 시나리오
* **UC-04 (오프라인 방문 예약 신청)**: 사용자가 상담 예약 폼에 필수 정보를 입력하고 제출하여 방문 예약을 완료하는 시나리오
* **UC-05 (카카오톡 빠른 문의 연결)**: 사용자가 플로팅 버튼을 클릭하여 실시간 메신저 상담으로 즉시 전환하는 시나리오

---

## 4. 상세 유스케이스 시나리오 (Detailed Use Case Scenarios)

* **유스케이스 명칭**: 오프라인 방문 예약 신청 (`UC-04`)
* **개요**: 학부모가 자녀의 수학 상담을 위해 희망 날짜, 시간, 학생 정보를 입력하고 예약을 접수합니다.
* **주요 흐름**:
1. 사용자가 랜딩페이지 하단의 '방문 예약' 섹션으로 이동합니다.
2. 학생 이름, 학년, 학부모 연락처, 희망 상담 날짜 및 시간을 입력합니다.
3. '상담 예약하기' 버튼을 클릭합니다.
4. 시스템이 입력값의 유효성(전화번호 형식, 필수 항목 누락 여부)을 검증합니다.
5. 검증 완료 후, 예약 완료 안내 팝업 또는 인라인 메시지를 출력하고 폼을 초기화합니다.



---

## 5. 주요 단계 및 이벤트 흐름 (Main Steps and Flow of Events)

| 단계 | 액터 (사용자) 행동 | 시스템 응답 및 처리 |
| --- | --- | --- |
| **1** | 웹 브라우저를 통해 랜딩페이지 루트(`/`)에 접속한다. | 상단바, 히어로 배너, 학원 소개 등 초기 1페이지 뷰를 렌더링한다. |
| **2** | 상단바 메뉴를 클릭하거나 마우스로 스크롤을 내린다. | 스무스 스크롤(Smooth Scroll) 효과와 함께 해당 섹션으로 이동하며, 스크롤스파이가 활성화된다. |
| **3** | 레벨 진단 위젯의 문항을 선택하고 결과를 요청한다. | 응답 데이터를 기반으로 점수를 산출하고 맞춤형 추천 코스를 동적으로 렌더링한다. |
| **4** | 방문 예약 폼에 정보를 입력하고 제출 버튼을 누른다. | 입력 필드의 공백 및 형식 오류를 검사하고, 정상인 경우 완료 상태를 피드백한다. |

---

## 6. 대체 흐름 및 엣지 케이스 (Alternative Flows and Edge Cases)

* **방문 예약 폼 누락 또는 형식 오류 (Alternative Flow 1)**:
* 4단계에서 전화번호 형식이 올바르지 않거나 필수 항목이 누락된 경우, 시스템은 제출을 중단하고 해당 입력 필드 하단에 빨간색 경고 문구를 출력합니다.


* **레벨 진단 중도 변경 (Edge Case 1)**:
* 사용자가 진단 도중에 이전 문항으로 돌아가 답변을 수정할 경우, 실시간으로 최종 결과 산출 로직이 재계산되도록 처리합니다.



---

## 7. 선행 조건 및 후행 조건 (Preconditions and Postconditions)

* **선행 조건 (Preconditions)**:
* 사용자의 기기에 모던 웹 브라우저가 설치되어 있어야 합니다.
* 정적 리소스(HTML, CSS, JS)가 네트워크를 통해 정상적으로 로드되어야 합니다.


* **후행 조건 (Postconditions)**:
* 방문 예약 완료 시 사용자 화면에 접수 완료 상태가 명확히 표시됩니다.
* 레벨 진단 완료 시 적정 코스 안내 카드가 노출됩니다.



---

## 8. 비즈니스 규칙 및 제약 사항 (Business Rules and Constraints)

* **데이터베이스 미사용 제약**: 백엔드 DB가 없으므로 예약 정보는 브라우저 단에서 임시 처리되거나 이메일/문자 연동 API(외부 서비스)로 전송되어야 합니다.
* **비로그인 접근 보장**: 모든 콘텐츠는 로그인 절차 없이 누구나 즉시 열람할 수 있어야 합니다.

---

## 9. 예외 처리 절차 (Exception Handling Procedures)

* **입력 유효성 검증 실패**: 클라이언트 측에서 JavaScript를 활용해 실시간으로 유효성을 검사하여 잘못된 데이터 전송을 사전에 차단합니다.
* **UI 렌더링 예외 방지**: 모바일 화면에서 긴 텍스트나 위젯 컴포넌트가 오버플로우되지 않도록 반응형 그리드와 `word-break` 속성을 적용합니다.

---

## 10. 사용자 인터페이스 고려 사항 (User Interface Considerations)

* **상단바 고정 (Sticky Topbar)**: 스크롤 중에도 사용자가 언제든지 다른 섹션으로 이동할 수 있도록 화면 최상단에 상단바를 고정합니다.
* **터치 타겟 최적화**: 모바일 환경에서 학부모 사용자가 쉽게 터치할 수 있도록 버튼 및 입력 필드의 최소 높이와 여백을 넉넉하게 확보합니다.

---

## 11. 데이터 요구 사항 및 데이터 흐름 (Data Requirements and Data Flow)

* **방문 예약 데이터 구조**:
* `studentName`: 학생 성명 (String)
* `grade`: 학생 학년 (Select/Enum: 고1, 고2, 고3 등)
* `parentPhone`: 학부모 연락처 (String, 전화번호 패턴 검증)
* `preferredDateTime`: 희망 상담 일시 (Date/Time)


* **데이터 흐름**:
* 사용자 입력 (`View`) $\rightarrow$ 자바스크립트 유효성 검사 (`Controller`) $\rightarrow$ 성공 시 성공 메시지 렌더링 및 UI 업데이트 (`View`)



---

## 12. 보안 및 Privacy 고려 사항 (Security and Privacy Considerations)

* **개인정보 최소 수집**: 학부모 연락처와 학생 이름 등 최소한의 정보만 입력받으며, 세션 종료 시 브라우저 메모리에서 안전하게 관리되도록 합니다.
* **XSS 방어**: 사용자가 입력한 텍스트가 DOM에 직접 악성 스크립트로 실행되지 않도록 안전한 텍스트 노드로 처리합니다.
